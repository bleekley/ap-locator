AP Locator

Collect Cisco AP/CDP inventory and infer site addresses from your switch inventory.

Repository · Full user guide · Lab setup and diagrams

Install

git clone https://github.com/bleekley/ap-locator.git
cd ap-locator
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
cp controllers.example.csv controllers.csv

Edit the two local configuration files. Keep credentials, actual controller lists, and customer data private. For PowerShell and per-controller credential overrides, see the full guide.

Preview without a network

python examples/offline_demo.py

Open output/demo/ap_location_report.xlsx. All demo data is synthetic.

Collect and correlate

python src/collect.py
python src/correlate.py path/to/switch_inventory.xlsx

Supply inventory columns hostname, mgmt_ip, and street_address. CSV is also accepted. Extra columns appear with an inventory_ prefix.

Read the workbook

  1. Run Summary: completeness, source, timestamps and match count.
  2. Controller Status: every requested controller and outcome.
  3. AP Locations: AP details, match method and location status.
  4. Per-Site Summary: counts and models, including unresolved APs.
COMPLETE means collection succeeded for the listed controllers, not that every location is known. Reports reject incomplete runs by default; --allow-partial explicitly generates a labeled subset. Check timestamps: a failed report attempt leaves the old workbook unchanged.

Investigate exceptions

Duplicates, missing addresses and absent neighbors remain UNKNOWN. MAC tracing produces a candidate for manual verification and never treats missing CDP as confirmed access-port placement. Model compatibility and replacement decisions require the target release's Cisco documentation.

The current reliability changes passed offline tests. Fresh live validation and a real multi-switch trace remain outstanding. The full guide is the maintained operational reference.
